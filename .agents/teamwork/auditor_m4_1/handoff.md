### ۲. بازرسی اصالت متد `update_study_note` و روت `PUT /api/v1/notes/{note_id}`

  ```python
  def update_study_note(self, note_id: str, user_id: str, data: Dict[str, Any]) -> Optional[Dict[str, Any]]:
      """Updates a study note belonging to the student."""
      for note in self.notes:
          if note.get("id") == note_id and note.get("user_id") == user_id:
              for key, val in data.items():
                  if val is not None:
                      note[key] = val
              return note
      return None
  ```
- در `backend/app/api/v1/endpoints/notes.py` (خطوط ۳۷-۴۹):

  ```python
  @router.put("/{note_id}", response_model=StudyNoteResponse, summary="Update student study note")
  def update_note(note_id: str, req: StudyNoteUpdate, user: dict = Depends(get_current_user)):
      updated = note_service.update_study_note(
          note_id=note_id,
          user_id=user["id"],
          data=req.dict(exclude_unset=True)
      )
      if not updated:
          raise HTTPException(status_code=404, detail="یادداشت مورد نظر یافت نشد یا دسترسی به آن مجاز نیست.")
      return updated
  ```

## ۲. زنجیره منطقی (Logic Chain)

۱. **عدم وجود تقلب یا خروجی سخت‌کدشده:** مشاهدات ۱ و ۴ ثابت می‌کنند که آزمون‌ها از کلاینت استاندارد FastAPI `TestClient` استفاده می‌کنند که از تمامی لایه‌های میان‌افزار (`RateLimitMiddleware`)، تزریق وابستگی (`get_current_user`, `get_current_admin`)، روترها و سرویس‌ها عبور می‌کند. هیچ گزاره `assert True` یا شبه‌پیاده‌سازی وجود ندارد.
۲. **اصالت چرخه کامل یادداشت‌ها و ایزولاسیون داده‌ها:** طبق مشاهده ۲ و آزمون مستقل، متدهای اضافه، ویرایش، حذف و فهرست یادداشت‌ها در `NoteService` به تفکیک `user_id` عمل می‌کنند. درخواست به‌روزرسانی یادداشت غیرمتعلق به کاربر با کد ۴۰۴ رد شده و از آسیب‌پذیری‌های IDOR (Insecure Direct Object Reference) جلوگیری می‌کند.
۳. **امنیت استریم صوتی و دفاع لایه‌ای:** طبق مشاهده ۱ و آزمون مستقل تک‌بایتی، بررسی توکن امضاشده DRM دارای اولویت مطلق است و پیش از هرگونه ارزیابی بازه یا اسلایس انجام می‌شود. همچنین سرآیندهای بازگشتی (`Accept-Ranges: bytes` و `Content-Range: bytes {start}-{end}/{total}`) کاملاً مطابق RFC 7233 تنظیم می‌شوند.
۴. **دفاع در برابر Replay Attack بانکی:** متد `verify_payment` با قفل رشته‌ای اتمیک (`with self._lock:`) وضعیت‌های `paid` و `failed` را مسدود نموده و اجازه احیای مجدد توکن‌های مصرف‌شده را نمی‌دهد.
